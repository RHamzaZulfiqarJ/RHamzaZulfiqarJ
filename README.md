### The work, in one signal

I turn ambiguous business workflows into software with sharp boundaries, observable behavior, and interfaces people can actually operate.

My projects sit where product engineering meets applied intelligence: multi-tenant CRMs, real-time financial systems, AI-assisted publishing, and explainable security models. I’m most interested in the difficult middle—the point where a compelling prototype has to become a dependable system.

```text
messy workflow  ──►  explicit model  ──►  secure boundary  ──►  useful interface
       ▲                                                              │
       └──────────────────── measure · learn · refine ──────────────────┘
```

### My build matrix

| Responsibility | Tools I reach for | What I optimize |
|---|---|---|
| **Product surface** | Next.js, React, TypeScript, Tailwind | clarity, accessibility, fast feedback |
| **Service boundary** | FastAPI, Node.js, Server Actions, Zod | contracts, validation, failure behavior |
| **Data layer** | PostgreSQL, Supabase, Prisma, SQLAlchemy | tenant isolation, auditability, query shape |
| **Intelligence layer** | PyTorch, RAG, FAISS, Gemini, LangChain | explainability, evaluation, human control |
| **Delivery layer** | Docker, Kubernetes, Vercel, MLflow, Vitest | repeatability, observability, release confidence |

### The rules behind the code

```yaml
interfaces:     boring enough to trust
data_access:    scoped before queried

deployments:    rehearsed before production
documentation: part of the product
```
